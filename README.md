# Finance Assistant

Семантический поиск по финансовой отчётности. По вопросу на английском языке находит пять близких по смыслу фрагментов PDF и выводит их текст, страницы и оценки сходства.

Текущая версия работает с отчётом Coca-Cola за 2022 год из [FinanceBench](https://github.com/patronus-ai/financebench). Это поисковая часть будущего RAG-сервиса. Генерация ответов LLM, векторная БД, API и оценка на вопросах бенчмарка пока не реализованы.

## Пайплайн

```text
PDF → страницы → чанки → эмбеддинги → сохранение на диск
Вопрос → эмбеддинг → сравнение с готовыми векторами чанков → top-5
```

- PyMuPDF извлекает текст отдельно для каждой страницы.
- LangChain `RecursiveCharacterTextSplitter` делит страницы на фрагменты до 500 символов с целевым перекрытием 50 символов.
- Sentence Transformers `all-MiniLM-L6-v2` создаёт нормализованные векторы размерности 384.
- NumPy сохраняет векторы в `.npy`; поиск загружает их и кодирует только вопрос.
- Скалярное произведение нормализованных векторов даёт косинусное сходство. Это оценка близости, а не вероятность правильного ответа.
- Чанки сохраняют документ, страницу и номер фрагмента внутри страницы.

Для текущего отчёта подготовлены 183 страницы и 1745 чанков. Форма массива векторов — `(1745, 384)`.

## Установка

Требуется Python 3.11 или новее. Текущее окружение проверялось на Python 3.14 и macOS с Apple M2 Pro. Для установки пакетов и первой загрузки модели нужен интернет.

Все команды выполняются из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

**Перед установкой:** текущую запись зависимостей без кавычек в `pyproject.toml` необходимо исправить. Имена пакетов должны быть строками:

```toml
dependencies = [
    "pymupdf",
    "langchain-text-splitters",
    "sentence-transformers",
    "numpy",
]
```

Режим `-e` позволяет изменять код в `src/` без переустановки пакета. В VS Code выберите интерпретатор `.venv/bin/python`.

## Данные

Скачайте `COCACOLA_2022_10K.pdf` из [папки FinanceBench](https://github.com/patronus-ai/financebench/tree/main/pdfs) и поместите в `data/raw/COCACOLA_2022_10K.pdf`.

PDF и результаты обработки исключены из Git. После клонирования репозитория их нужно подготовить локально.

## Запуск

### 1. Извлечение и чанкинг

```bash
python scripts/check_pdf.py
```

Создаёт два файла:

- `data/processed/COCACOLA_2022_10K_pages.json` — текст и источник каждой страницы.
- `data/processed/COCACOLA_2022_10K_chunks.json` — фрагменты с документом, страницей и номером чанка.

Скрипт также проверяет чтение сохранённых страниц и выводит статистику чанкинга.

### 2. Подготовка векторов

```bash
python scripts/check_embeddings.py
```

При первом запуске скачивает энкодер, вычисляет векторы и сохраняет `data/processed/COCACOLA_2022_10K_embeddings.npy`. Затем загружает массив обратно и сравнивает с исходным. Для текущих данных ожидаются форма `(1745, 384)` и результат сравнения `True`.

### 3. Поиск

```bash
python scripts/search.py
```

Вопрос задаётся переменной `question` внутри `main()` в `scripts/search.py`, например:

```python
question = "What was Coca-Cola's revenue in 2022?"
```

Результат — пять фрагментов с номерами страниц и оценками сходства. Связь текста и вектора сохраняется по позиции: `chunks[i]` соответствует `embeddings[i]`.

Для нового вопроса запускайте только поиск. При изменении PDF или чанкинга повторите все этапы. При замене энкодера пересоздайте векторы и укажите ту же модель в поиске. Подготовка перезаписывает существующие результаты.

## Структура

```text
src/finance_assistant/
    __init__.py
    pdf.py                   # Извлечение текста страниц
    chunking.py              # Разбиение страниц
scripts/
    check_pdf.py             # Подготовка JSON страниц и чанков
    check_embeddings.py      # Вычисление и сохранение векторов
    search.py                # Поиск по готовым векторам
data/
    raw/                     # Исходные PDF
    processed/               # JSON и .npy
reports/                     # Для будущих результатов оценки
```

## Текущие ограничения

- Пути и документ заданы в коде. Запускать скрипты нужно из корня репозитория.
- В `pdf.py` остался демонстрационный код на уровне модуля: при импорте открывается конкретный PDF и печатается начало документа. Его нужно удалить, оставив импорты и функцию.
- В `search.py` при несовпадении количества чанков и векторов выполнение останавливается с `ValueError`.
- Одинаковое количество записей не гарантирует одинаковый порядок или актуальность векторов. Проверки версии данных и модели пока нет.
- Извлечение текста может терять пробелы и структуру таблиц. Чанкинг может отделить значение от названия показателя или года.
- Размер фрагментов считается символами; контроль токенного лимита энкодера пока отсутствует.
- Поиск перебирает все векторы. Векторная БД, ANN-индекс, гибридный поиск и реранкер пока не подключены.
- Скрипты `check_*` проверяют отдельные операции, но не заменяют автоматическую оценку качества поиска и ответов.

Номер страницы начинается с 1 и соответствует позиции в PDF, а не обязательно напечатанному номеру. В разметке FinanceBench нумерация начинается с 0 — это нужно учитывать при оценке. Эталонные ответы не должны попадать в поисковый индекс.
